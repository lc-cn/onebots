# 损坏配置恢复契约（阶段三待办，未实现）

本文是待实施设计，不是已交付功能或验收结果。当前管理服务在 YAML 损坏后仍可在线，但配置快照及正常草稿链路依赖解析成功；当前应用备份是配置文档，不能代替坏 YAML 的原始字节备份。

## 状态与公开边界

| 配置来源状态 | 管理端允许看到的信息 | 行为 |
| --- | --- | --- |
| `ready` | 现有脱敏配置、基础版本、可信 Schema | 正常草稿、校验、应用 |
| `damaged` | 固定原因 `INVALID_YAML`、原始摘要、活动运行版本、是否可修复 | 显式创建修复草稿；不返回原文 |
| `unavailable` | 固定不可用原因 | 不写入；先修复本地权限或文件边界 |

- 文件版本统一为原始字节的 SHA-256。不能把坏文件解释为 `{}`，也不能用解析后的 JSON 摘要替代原始摘要。
- 缺失、权限失败、符号链接、硬链接、超限等不是可直接覆盖的语法损坏，不自动初始化或修复。
- HTTP 不返回坏文件全文、片段、解析错误原文、秘密值或备份绝对路径；备份没有公开下载入口。
- 损坏配置不提供可靠的插件选择信息。禁止从坏文本猜测选择、自动启用扩展或扫描任意包。

## 修复草稿与私有备份

新增显式修复入口，输入基础版本 `{generationId, configRevision}` 和策略 `new-empty`。这是用户明确选择重新建立替代配置，不表示原配置为空。普通 `create` 不能悄悄进入修复模式。

1. 核对活动运行版本与当前原始文件摘要。
2. 将本次读取的原始字节保存为管理域私有备份；备份采用不透明标识，目录权限 `0700`、文件 `0400`。
3. 用实际复制字节核验摘要，经文件同步、原子重命名和目录同步后，才持久化修复草稿与备份引用。已有备份必须重新核验，不能只相信文件名。
4. 初始替代文档仅显式包含空的平台、协议、框架选择；不复制无法解析的字段、不填账号或凭据。
5. 用户继续使用现有账号、协议、字段和秘密操作建立配置，再显式校验与应用。

修复草稿的 Schema 来自当前已验证运行版本。内置运行版本通过可信已安装目录及显式选择执行隔离探测；没有可信扩展证据时只提供基础表单和空选择，不能假设损坏文件原来加载了哪些扩展。

私有备份不能因正常草稿清理而删除；应保留到独立、显式的数据保留策略允许清理为止。本设计不提供自动删除备份行为。

## 验证收据与唯一应用事务

草稿、收据及操作日志显式记录 `mode: normal | repair`。修复模式额外绑定原始文件摘要及私有备份引用，并将这些信息纳入版本和一致性检查。旧格式只按正常模式读取，不能升级成修复授权。

校验仍使用现有隔离 worker 和目标运行版本规则，不创建账号，也不写源文件。验证前后、应用前均检查基础原始摘要、活动版本、草稿版本和运行指纹。客户端应用请求仍只有操作 ID 与收据 ID，不能直接传入正文、模式或备份位置绕过验证。

修复与正常应用共用 `runConfigurationTransaction` 和现有生命周期队列，不另建并行队列：

1. 核验备份摘要等于基础原始摘要，并确认当前来源仍是对应损坏文件。
2. 持久化候选文档、原始备份引用、模式、原期望状态和操作意图。
3. 停止旧网关，确认没有存活或身份未知的子进程。
4. 以原始摘要作 CAS，将合法候选 YAML 原子写入。
5. 原期望为运行时等待新网关 ready 后提交；原期望为停止时不启动。

`normal` 与 `repair` 可以复用事务阶段，但备份和回退策略必须区分：修复备份是原始字节，不能送入现有 JSON 文档读取器重新序列化。

## 失败与冷中断

- 备份未可靠落盘：不停止网关，不修改源文件，不签发可应用的修复收据。
- 新网关可确认启动失败，且没有存活或未知子进程：仅在文件仍属于本次操作时，以 CAS 恢复原始坏字节；操作记为失败、已回退、来源仍损坏。保留原期望状态，但**不得启动原坏配置**。
- 已恢复原始字节且结果明确时，允许用户重新建立修复草稿；不能把可确认的修复失败永久当成未知事务。
- 持久化结果未知、文件被外部改变或子进程身份不明：停止后续不安全动作，保留诊断；不盲覆盖、不声称回退成功。
- 原网关可能仍持有损坏前的内存配置，但不承诺能从坏文件重建它。
- 冷启动遇到未完成操作：标记中断并保持恢复门禁，不自动重放。当前文件匹配候选摘要也不是网关曾 ready 的证明。
- 本地显式对账绑定操作 ID 和当前原始摘要；只有确认没有遗留子进程、原备份与候选均通过摘要验证时，才允许 CAS 恢复原始备份并记为已对账失败。
- 当前文件出现第三种摘要或 PID 无法证明归属时，不执行恢复写入。继续采用候选配置需要重新验证及显式操作。

## 最小变更范围

| 模块 | 待实现变更 |
| --- | --- |
| `configuration-file` | 区分可解析、语法损坏与不可用；管理域原始读取、备份及 CAS 字节恢复 |
| `configuration-workspace` | 损坏状态快照和独立修复上下文，不依赖原 YAML 解析 |
| `configuration-store` / `configuration-drafts` | 显式修复草稿、模式和备份绑定；复用现有编辑投影 |
| `configuration-validation` | 收据绑定修复来源与模式，复用隔离校验 |
| `configuration-application` | 原始字节备份策略、修复回退和中断对账；保持唯一队列 |
| 配置服务、API、统一客户端及界面 | 状态联合、显式修复操作、固定诊断；禁止公开原始文件 |

本设计不扩展系统服务、操作系统迁移或 TUI 架构。

## 验收要求（尚未执行）

- 含秘密、非 ASCII 和 CRLF 的坏 YAML 能逐字节私有备份；公开快照、异常与收据不含原文。
- 备份失败不产生停机或源写入；备份被篡改时拒绝应用。
- 创建、校验及应用任一阶段外部修改原始文件均冲突拒绝，不丢失新文件。
- 正常与修复模式混用、过期收据、运行版本变化均不能绕过授权。
- 真实运行与停止状态分别完成修复；新 ready 失败后恢复原始字节且不重启坏配置。
- 修复与版本切换、启动并发时不能穿过同一队列。
- 各持久化阶段注入中断，重启后保留诊断与门禁；本地对账只恢复摘要匹配且进程状态明确的操作。
